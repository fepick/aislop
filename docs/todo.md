# TODO

이 문서는 사용자가 구현·수정·검토하고자 하는 요소를 관리하는
프로젝트 백로그다.

## 공통 규칙

- agent는 프롬프트 실행 시작 시 이 문서를 읽기 전용으로 확인한다.
- agent는 사용자의 명시적 지시 없이 이 문서를 생성·수정·삭제·정렬·이동하지 않는다.
- agent는 TODO의 항목을 임의로 세분화하거나 새 항목을 추가하지 않는다.
- 실제 코드·에셋·설정 파일 변경은 사용자의 명시적 구현 승인 후에만 수행한다.
- 항목이 없는 섹션은 분석, 계획, 구현 대상이 아니다.
- 계획 문서는 `docs/plans/`에 작성한다.
- 계획 문서에는 관련 TODO 항목, 영향 범위, 위험 요소, 검증 방법을 기록한다.

## 버그 픽스

이 섹션의 항목은 다른 개발 항목보다 계획 수립 우선순위가 높다.

agent는 각 항목에 대해 다음을 수행한다.

1. 재현 조건과 재현 절차를 확인한다.
2. 관련 코드·에셋·설정·시뮬레이션 결과에 미칠 영향을 분석한다.
3. 원인 가설과 수정 방안을 작성한다.
4. 회귀 위험과 검증 방법을 제안한다.
5. `docs/plans/`에 버그 수정 계획을 작성한다.

중요: 버그 수정 계획의 우선순위가 높을 뿐,
사용자의 명시적 승인 없이 코드나 에셋을 수정하지 않는다.

## 개발 확정

이 섹션의 항목은 향후 구현 대상으로 확정된 기능 또는 변경 사항이다.

agent는 각 항목에 대해 다음을 수행한다.

1. 현재 프로젝트 구조와의 영향 범위를 분석한다.
2. 기존 전투 규칙, AI, 시뮬레이션, 렌더링, 결과 데이터와의 의존성을 확인한다.
3. 필요한 설계 변경, 데이터 구조, 테스트 항목을 제안한다.
4. 이후 구현 계획에 반영한다.

중요: 이 섹션은 계획 반영 승인 상태를 의미한다.
실제 구현은 사용자가 특정 항목 또는 plan의 구현을 명시적으로 요청한 경우에만 수행한다.

## 검토 필요

이 섹션은 구현 또는 계획 반영이 아직 확정되지 않은 후보 항목이다.

agent는 각 항목에 대해 다음을 수행한다.

1. 기능 추가 또는 변경의 영향 범위를 분석한다.
2. 기대 효과, 비용, 위험 요소, 선행 조건을 사용자에게 설명한다.
3. 필요한 결정 사항과 선택지를 제안한다.

agent는 이 섹션의 항목을 구현 계획에 반영하지 않는다.
agent는 사용자의 명시적 지시 없이 이 항목을 다른 섹션으로 이동하지 않는다.

## 검토 불필요

아래 항목은 사용자 개발 편의를 위한 메모다.

- agent는 이 항목을 분석, 계획, 구현 대상으로 취급하지 않는다.
- agent는 이 항목을 다른 섹션으로 이동하거나 구현 후보로 승격하지 않는다.
- 사용자가 명시적으로 요청할 때만 해당 항목을 다룬다.

1. 스테이지 구성
2. 스테이지별 상대 NPC 디자인 및 에셋 생성
3. 스토리 부여
4. 아이템 구현 — (유니크) 카본 깔창: 로프 드롭킥의 전진 거리 증가
5. 아이템 구현 — (레어) 하이힐: 발차기 치명타 확률 증가
