# 03. 전투 피드백 후속 수정 계획

작성일: 2026-07-30  
관련 문서: `docs/todo.md`  
대상: 버그 픽스 3건, 개발 확정 2건  
목표: 밀기 스프라이트 누출과 무음 시작을 수정하고, 로프 드롭킥의 카운터 면역 및 0.3초 지연 카운터와 특수기 안내 문구를 결정적으로 구현한다.

## 1. 확인된 현재 상태와 구현 순서

- 밀기 프레임을 543×724로 분리하면 오른쪽 끝에 다음 드롭킥 프레임의 피부색 픽셀이 포함된다. 렌더러의 프레임 인덱스 오류가 아니라 원본 P1/P2 시트의 프레임 경계 오염이다.
- 두 WAV에는 실제 신호가 있고 최대 음량은 각각 -1.2dB, 0dB이다. 게임은 페이지 로드 직후 자동 진행하지만 `AudioContext`는 `관전 시작` 클릭에서만 활성화되므로, 그 전의 공격·피격 이벤트는 소리 없이 버려진다.
- `applyHits`는 공격 유형을 구분하지 않고 모든 피격에 카운터 확률과 RNG를 적용하므로 로프 드롭킥도 카운터 대상이다. 성공한 카운터 피해도 현재 같은 tick에 즉시 적용된다.
- 구현 순서는 **스프라이트·사운드 버그 → 로프 드롭킥 카운터 면역 → 지연 카운터 → 로프 드롭킥 문구**로 한다. 규칙 변경 뒤 `rulesVersion`과 결과 스키마 변경 여부를 갱신하고, 표현 변경이 시뮬레이션 결과에 영향을 주지 않게 한다.

## 2. 우선 버그 픽스

### 밀기 프레임 경계 오염 제거

**관련 TODO:** 버그 픽스 1

- P1과 P2 시트의 세 번째 셀(`PUSH`, x=1086~1628) 오른쪽 경계에 섞인 다음 프레임 픽셀만 투명화한다. 전체 시트 크기 2172×724, 네 셀의 543×724 구조, 기존 선수 본체, 피벗과 바닥선은 유지한다.
- 런타임에서 source rect를 임의로 축소하지 않는다. 에셋 자체를 교정하여 경기장 선수와 HUD 등 모든 소비자가 동일한 정상 프레임을 사용하게 한다.

**위험과 검증**

- 실제 밀기 손·팔 픽셀을 지우지 않도록 세 번째 셀만 전후 비교하고, 우측 경계의 분리된 연결 요소만 제거한다.
- P1/P2의 밀기 프레임을 단독 추출해 오른쪽 가장자리에 고립 픽셀이 없는지 자동 검사하고, 양 방향 렌더에서 다음 포즈 일부가 보이지 않는지 육안 확인한다.
- PNG 크기, RGBA, 네 프레임, 투명 배경과 P1/P2 색상 차이를 회귀 검사한다.

### 최초 관전부터 사운드가 출력되도록 시작 흐름 수정

**관련 TODO:** 버그 픽스 2

- 페이지 초기화 시에는 경기 객체와 첫 화면만 만들고 `paused = true`로 유지한다. 자동 전투를 시작하지 않는다.
- `관전 시작` 버튼의 동기 클릭 구간에서 `AudioContext`를 생성·resume한 다음 WAV를 decode하고 새 경기를 시작한다. 오디오 준비가 실패해도 경기는 시작하되 경고와 `소리 재시도`가 가능한 상태를 유지한다.
- `재개`, `재시작`, 키보드 `R`도 공통 `ensureAudio()`를 호출하되 이미 활성화된 context와 buffer는 재사용한다. 동일 이벤트 listener나 오디오 context를 중복 생성하지 않는다.
- 음원 준비 전 발생한 이벤트를 뒤늦게 재생하지 않는다. 시작 버튼은 decode 완료까지 준비 상태로 표시하고 중복 클릭을 막아, 실제 첫 tick부터 공격·피격 이벤트가 정상 재생되게 한다.

**위험과 검증**

- 브라우저 autoplay 정책 때문에 `resume()`은 반드시 클릭·키 입력 handler에서 시작한다. HTTP 정적 서버와 GitHub Pages 하위 경로에서 상대 음원 URL을 확인한다.
- mock `AudioContext`로 최초 시작, 재시작, pause/resume, decode 실패 후 재시도, 최대 4보이스 제한을 테스트한다.
- 수동으로 첫 공격에 “우!”, 첫 명중에 “뻑!”이 들리고 데미지가 큰 피격음이 더 큰지 Chrome/Safari에서 확인한다.

### 로프 드롭킥의 카운터 면역

**관련 TODO:** 버그 픽스 3

- 피격 처리 전에 `actionType === "ROPE_DROP_KICK"`이면 카운터 판정을 건너뛰고 기존 피해·치명타·넉백·분노 처리를 그대로 적용한다.
- 면역 공격에는 `countersAttempted`를 증가시키거나 counter RNG를 소비하지 않는다. 따라서 같은 seed의 이후 일반 공격 카운터 판정이 로프 드롭킥 유무 때문에 불필요하게 밀리지 않게 한다.
- 일반 `KICK`과 `PUSH`만 카운터 대상이며 AI에서 비활성화된 일반 `DROP_KICK`은 규칙상 카운터 가능 상태를 유지한다.

**위험과 검증**

- 로프 드롭킥에 counter RNG가 항상 성공하는 대역을 넣어도 `COUNTER` 이벤트가 없고 원래 피해가 적용되는지 검사한다.
- 일반 공격의 카운터 확률, 지표, 결정성과 로프 드롭킥의 단일 hit·치명타·KO 처리를 회귀 테스트한다.

## 3. 0.3초 지연 카운터

**관련 TODO:** 개발 확정 1

- 60Hz 고정 timestep에서 지연 시간을 정확히 18 tick으로 정의한다. 카운터 판정 성공 tick에는 원래 공격을 즉시 무효화하고 `COUNTER_TRIGGERED` 이벤트를 기록하지만 반격 피해는 아직 적용하지 않는다.
- 방어자에게 `pendingCounter`를 저장한다: 대상 ID, 남은 tick 18, 확정된 피해, 넉백 방향. 지연 중에는 새 AI 행동과 공격을 시작하지 않으며 일반 밀기 포즈를 미리 재생하지 않는다.
- 18 tick 뒤 방어자와 대상이 모두 생존해 있으면 저장된 대상에게 사거리 재판정 없이 반격을 적용하고 `COUNTER` 이벤트, 밀기 포즈, 파란 피해 숫자와 피격음을 발생시킨다. 카운터가 확정된 시점의 반격이므로 지연 중 위치 변화로 취소하지 않는다.
- 지연 중 방어자가 다른 동시 공격으로 KO되면 pending counter를 취소한다. 대상만 먼저 KO되거나 경기가 종료돼도 취소하며, 취소된 반격은 성공 지표와 피해량에 포함하지 않는다.
- `countersAttempted`는 확률 판정 시, `countersSucceeded`와 `counterDamageDealt`는 18 tick 뒤 실제 반격 적용 시 증가시킨다. pending counter는 재귀 카운터 대상이 아니며 한 선수당 하나만 유지한다.

**위험과 검증**

- 발동 tick부터 17 tick 동안 피해가 없고 정확히 18번째 tick에 한 번만 피해가 적용되는지 고정 tick 테스트를 작성한다.
- 지연 중 양측 카운터, 방어자/대상 KO, 경기 종료, pause/resume, 재시작 시 pending 상태 초기화를 검사한다.
- 관전/headless 결과 일치와 같은 seed 재현성을 확인하고, 즉시 카운터에서 지연 카운터로 바뀐 1,000경기 승률·KO율·평균 시간을 비교한다.

## 4. 로프 드롭킥 안내 문구

**관련 TODO:** 개발 확정 2

- 기존 `ACTION_STARTED` 이벤트에서 `actionType === "ROPE_DROP_KICK"`을 감지해 렌더러에 안내 항목을 생성한다. 코어 이벤트나 RNG 호출은 새로 추가하지 않는다.
- 붉은 글씨 `로프 드롭킥!`을 흰색 외곽선과 함께 선수 머리 위에 60 렌더 프레임 동안 표시한다. 항목에는 actor ID를 저장하고 매 렌더마다 현재 선수 좌표를 읽어 돌진 중에도 머리 위를 따라가게 한다.
- P1/P2가 같은 tick에 사용하면 각 선수 위에 각각 표시하며, 재시작·경기 종료 시 남은 안내 항목을 제거한다. headless 모드에는 렌더 상태를 만들지 않는다.

**위험과 검증**

- 화면 경계와 HUD에 겹치지 않도록 논리 화면 좌표에서 텍스트 폭과 y 좌표를 clamp한다.
- 일반 공격에는 표시되지 않고 로프 드롭킥 시작당 한 번만 생성되는지, P2 좌우 반전과 화면 흔들림 중에도 해당 선수를 따라가는지 확인한다.
- 안내 문구 활성화 전후에 같은 seed의 결과 JSON이 완전히 동일한지 검사한다.

## 5. 완료 기준

- 기존 13개 자동 테스트를 유지하고 프레임 경계, 오디오 시작·재시도, 로프 드롭킥 면역, 18 tick 카운터, 안내 문구 이벤트 매핑 테스트를 추가한다.
- 정적 서버에서 P1/P2 시트와 두 WAV가 HTTP 200으로 로드되고 브라우저 콘솔 오류가 없어야 한다.
- 1,000개 고정 seed에서 로프 드롭킥 카운터 0회, 일반 공격 카운터 발생, 일반 드롭킥 0회, 로프 드롭킥 및 밀기 사용 유지, 모든 경기 3,600 tick 이내 종료를 확인한다.
- 실행 흐름이나 컨트롤 설명이 달라지므로 `README.md`를 갱신한다. `docs/todo.md`의 항목 이동·삭제·완료 표시는 별도 사용자 지시가 있을 때만 수행한다.
