# 04. 스테이터스 시스템 및 설정 화면 계획

작성일: 2026-07-30  
관련 문서: `docs/todo.md`  
참고 에셋: `asset/play_sample/sample_setting.png`  
대상: 개발 확정 3건  
목표: 동일한 10점 기준의 원본 스테이터스와 파생 전투 수치를 분리하고, 10점 예산을 배분한 뒤 해당 설정으로 관전·headless 전투를 실행하는 설정 화면을 추가한다.

## 1. 현재 상태와 변경 원칙

- 현재 기본값은 `attackSpeed/power/defense/sharpness/luck/insight = 10`, `maxHealth = 100`이라 설정 화면에서 동일 단위로 배분하기 어렵다. `moveSpeed`는 존재하지 않는다.
- 현재 `attackSpeed`, `power`, `maxHealth`, `defense`, `insight`는 규칙에 일부 반영된다. `sharpness`와 `luck`은 함께 치명타 확률을 올리지만 새 요구에서 sharpness는 치명타 배율, luck은 미사용이므로 역할을 재배치해야 한다.
- 원본 스탯은 모두 기준값 10으로 통일하고, 체력·공격 주기·이동 배율처럼 게임이 실제 사용하는 값은 순수 함수로 계산한 `derivedStats`에 둔다. UI, 관전, headless, 결과 JSON이 같은 계산 함수를 사용한다.
- `luck`은 결과와 설정 화면에 보존하되 현재 규칙과 전투력 계산에는 사용하지 않는다. 예산을 낭비하지 않도록 `현재 버전 미적용`으로 표시하고 증감 버튼을 비활성화한다.
- 이번 계획에는 `검토 필요`의 2배속, 3라운드, 체력 기반 캐릭터 크기 변경을 포함하지 않는다.

## 2. 스테이터스 공식과 근거

### 원본 스탯과 파생값

기본 원본 스탯은 아래처럼 모두 10으로 둔다.

```js
{
  attackSpeed: 10,
  moveSpeed: 10,
  power: 10,
  maxHealth: 10,
  defense: 10,
  sharpness: 10,
  luck: 10,
  insight: 10
}
```

| 항목 | 적용 공식 | 기준값 10 | 예산 10점을 한 항목에 투자한 값 | 설정 근거 |
|---|---|---:|---:|---|
| `attackSpeed` | `timingScale = clamp(1 - 0.035 × (stat - 10), 0.65, 1.35)` | 공격 startup/active/recovery/cooldown 100% | 65% | 한 점당 공격 주기 3.5% 감소로 효과를 쉽게 예측할 수 있게 한다. 20에서 기존 역수식의 2배 공격 속도 대신 약 1.54배로 제한해 최우선 투자 고착을 막는다. |
| `moveSpeed` | `moveScale = clamp(1 + 0.04 × (stat - 10), 0.60, 1.60)` | 접근 및 로프 드롭킥 속도 100% | 140% | 한 점당 4%는 화면에서 체감되면서도 10점 투자로 링을 과도하게 횡단하지 않는 범위다. 접근 속도와 로프 드롭킥 active 구간 속도에만 곱하므로 active 시간이 같을 때 이동 거리도 같은 비율로 증가한다. |
| `power` | `baseDamage + power × 0.60 - defense × 0.35` | 기존 피해 유지 | 타격당 +6 | 기존 0.2 규칙과 결과의 연속성을 유지한다. 방어보다 계수가 높지만 모든 투자 효과가 명확하고 최소 피해 1은 유지된다. |
| `maxHealth` | `derivedMaxHealth = 50 + maxHealth × 5` | 100 HP | 150 HP | 모든 원본 스탯을 10 기준으로 통일하면서 한 점당 체력 5%를 제공한다. UI에는 원본 10과 파생 체력 100을 각각 현재 스탯/전투 미리보기로 구분한다. |
| `defense` | 피해 공식의 `defense × 0.35` | 공격 1회당 3.5 감소 전 반올림 | 공격 1회당 7.0 감소 전 반올림 | 현재 공식을 유지해 기존 밸런스와 최소 피해 정책을 보존한다. 여러 번 맞는 경기 특성상 체력보다 누적 효율이 커질 수 있어 배치 검증한다. |
| `sharpness` | `criticalMultiplier = clamp(1.25 + sharpness × 0.025, 1.25, 2.00)` | 1.50배 | 1.75배 | 요구대로 발동 확률이 아니라 치명타 피해에만 연결한다. 한 점당 0.025배로 두어 고정 12% 확률에서 기대 피해 증가가 완만하다. |
| `luck` | 현재 규칙 미적용 | 변화 없음 | 배분 불가 | 성장성 시스템이 없는 현재 버전에서 임의의 전투 효과나 RNG 호출을 만들지 않는다. |
| `insight` | `counterChance = clamp(0.05 + insight × 0.01, 0.05, 0.45)` | 15% | 25% | 이미 구현된 카운터 공식과 독립 RNG를 유지한다. 한 점당 1%p라 UI 설명과 실제 확률이 일치한다. |

치명타 확률은 luck와 sharpness에서 분리해 현재 버전에서 모든 선수에게 고정 12%를 적용한다. 이 값은 치명타가 관전 중 드물지 않게 보이면서 sharpness 10의 1.5배 피해가 평균 피해를 약 6% 높이는 수준이라 기본 전투를 지배하지 않는다.

### 규칙 적용 위치

- `deriveStats(rawStats)`가 최대 체력, 공격 timing scale, 이동 scale, 치명타 확률·배율, 방어 보정, 카운터 확률을 반환한다. 게임과 설정 화면은 이 함수를 중복 구현하지 않는다.
- 공격 startup/active/recovery/cooldown은 각각 timing scale을 곱한 뒤 최소 1 tick으로 반올림한다.
- `APPROACH` 속도와 `ROPE_DROP_KICK`의 active 이동 속도에 move scale을 곱한다. 일반 드롭킥은 AI 확률 0 상태를 유지하며 직접 사용 경로가 생기기 전까지 moveSpeed 적용 대상에서 제외한다.
- 치명타 판정은 고정 12%로 수행하고, 성공 시 공격자의 derived critical multiplier를 피해에 곱한 뒤 내림한다.
- 선수 생성 시 `health = derivedStats.maxHealth`로 설정하고 HUD도 현재 체력/파생 최대 체력을 사용한다.
- 규칙 변경으로 `rulesVersion`을 올린다. 원본/파생 스탯 구조와 기본 `maxHealth` 단위가 바뀌므로 `resultSchemaVersion`도 올리고 결과에 `rawStats`, `derivedStats`, `unusedStats: ["luck"]`을 기록한다.

### 전투 미리보기와 종합 전투력

- 최소 데미지: 현재 선수의 `PUSH` 비치명 피해를 다음 상대의 방어에 적용한 값.
- 최대 데미지: `ROPE_DROP_KICK`의 기본 피해와 로프 보너스에 치명타 배율을 적용한 값.
- 치명타 확률/배율: 고정 12%와 derived multiplier.
- 체력/방어력/카운터 확률: derived 최대 체력, `defense × 0.35`의 공격당 방어 보정, derived counter chance.
- 전투력은 기준 전투력 1,000에 기준값 10 대비 투자 가중치를 더해 계산한다.

```text
combatPower =
  round(1000
    + (attackSpeed - 10) × 25
    + (moveSpeed - 10) × 10
    + (power - 10) × 30
    + (maxHealth - 10) × 25
    + (defense - 10) × 20
    + (sharpness - 10) × 5
    + (insight - 10) × 12)
```

- power·attackSpeed는 모든 명중의 피해/주기에 직접 작용해 높은 가중치를 둔다.
- maxHealth는 한 점당 5 HP이므로 power와 비슷한 생존 기여를 기대해 25를 둔다.
- defense는 다단 피격에서 누적되지만 최소 피해와 상대 power에 따라 가치가 달라 20으로 제한한다.
- moveSpeed는 위치와 특수기 거리를 바꾸지만 직접 피해를 보장하지 않아 10, insight는 확률 효과라 12를 둔다.
- sharpness는 12% 확률에서만 작동해 5, luck는 미사용이라 0이다.
- 이 값은 UI 비교용 지표이며 피해, AI 판단, 승패에 되쓰지 않는다. 1,000경기 민감도 분석으로 실제 승률과 방향이 반대인 가중치가 있는지만 검증하고 자동 밸런싱은 하지 않는다.

## 3. 설정 화면과 데이터 흐름

### 화면 구성

- `sample_setting.png`의 정보 위계와 2열 구성을 참고하되 이미지를 배경으로 사용하거나 그대로 복제하지 않고 HTML/CSS로 만든다.
- 좌상단: 남은 예산 10, P1 초상화, 8개 원본 스탯, 각 행의 감소/현재값/증가 버튼. luck 행은 미적용 설명과 비활성 버튼을 표시한다.
- 좌하단: 최소·최대 데미지, 치명타 확률·배율, 체력, 방어 보정, 카운터 확률을 현재 배분과 상대 스탯으로 즉시 다시 계산한다.
- 우상단: Blue Bull 시트의 스탠딩 프레임, 이름, 고정 설명 `강한 힘과 방어력을 앞세워 압박하는 느린 인파이터.` 및 주요 스탯을 표시한다.
- 우하단: P1/P2 종합 전투력, `초기화`, `전투 시작` 버튼. 좁은 화면에서는 좌측 블록 다음 우측 블록 순서의 단일 열로 바꾼다.

### 기준값·예산·상대 설정

- `STAT_BUDGET = 10`을 UI 코드가 아닌 설정 상수로 둔다.
- 설정 화면 진입 시 P1의 `baseStats`를 깊은 복사해 고정하고, `allocatedStats`와 `remainingBudget`을 별도로 관리한다.
- 증가 버튼은 활성 스탯이고 예산이 1 이상일 때만 +1과 예산 -1을 원자적으로 적용한다. 감소 버튼은 현재값이 baseStats보다 클 때만 -1과 예산 +1을 적용한다.
- 초기화는 allocatedStats를 baseStats 사본으로 교체하고 예산을 10으로 되돌린다. luck와 baseStats 아래로는 감소할 수 없다.
- 현재 유일한 다음 상대 Blue Bull의 원본 스탯은 `attackSpeed 8, moveSpeed 8, power 12, maxHealth 10, defense 11, sharpness 10, luck 10, insight 10`으로 고정한다. 참고 화면의 강한 힘·방어와 느린 발이라는 설명을 실제 규칙에 일치시키고 상대 설정을 `PLAYER_CONFIGS`에 한곳에서 관리한다.

### 화면 전환과 실행

- 문서에는 `setup-screen`과 `battle-screen` 두 영역을 두고 `hidden` 상태로 전환한다. 최초 로드에서는 설정 화면만 표시한다.
- `전투 시작`은 현재 배분을 불변 snapshot으로 만들고 P1/P2 원본 스탯을 `Game`에 전달한 뒤 전투 화면으로 전환하고 기존 오디오 준비 흐름을 실행한다.
- 관전 재시작은 같은 설정 snapshot과 seed를 사용한다. `설정으로 돌아가기`는 진행 중 경기를 정지하고 설정 화면으로 복귀하되 현재 배분과 남은 예산을 유지한다.
- headless 1/100/1,000회도 같은 P1/P2 snapshot을 `runMatch`와 `BatchRunner`에 전달한다. 실행 중 설정 객체가 바뀌지 않도록 batch 시작 시 복사한다.
- 단일/배치 결과와 다운로드 JSON에 양측 원본·파생 스탯 및 stat rules version을 포함해 같은 seed라도 설정이 다른 결과를 구분한다.

## 4. 영향 범위, 위험과 검증

### 구현 범위

- 설정/규칙 계층에 스탯 정의, 파생값 계산, 전투력과 미리보기 순수 함수를 추가한다.
- Player/Game/시뮬레이션 runner는 원본 스탯 snapshot을 받아 파생값으로 전투를 실행하고, UI는 설정 화면 상태와 화면 전환을 관리한다.
- 기존 Canvas 렌더러는 HUD 최대 체력 참조만 파생값으로 바꾸고 전투 결과에 영향을 주지 않는다.

### 자동 검증

- 각 공식의 기준값 10과 경계값, attackSpeed timing 반올림, moveSpeed 접근·로프 이동 거리, power/defense 피해, maxHealth 100, sharpness 배율, 고정 치명타 확률, insight 확률, luck 무효를 단위 테스트한다.
- 예산 합계 불변식, 0 예산 증가 차단, 기준값 이하 감소 차단, luck 배분 차단, 초기화와 현재 배분 보존을 테스트한다.
- 설정 화면 미리보기와 실제 첫 전투의 파생값·피해가 같은 순수 함수 결과인지 검사한다.
- 같은 seed+같은 설정의 재현성, 관전/headless 일치, 설정이 다른 경기의 결과 메타데이터 구분, 배치 중 snapshot 불변성을 검사한다.
- 기본 대 기본 및 각 활성 스탯에 10점을 몰아준 조건을 동일한 1,000 seed로 실행해 승률, KO율, 평균 시간, 로프 드롭킥·카운터 빈도와 전투력 지표 방향을 비교한다.

### 위험과 대응

- 기존 `maxHealth: 100` 결과와 새 원본 `maxHealth: 10`은 의미가 다르므로 schema/rules version 없이 혼용하지 않는다. 이전 JSON을 새 설정 화면으로 자동 로드하지 않는다.
- moveSpeed가 높을 때 로프 드롭킥이 상대를 통과하거나 링 밖으로 나가지 않도록 swept hit와 링 clamp 테스트를 유지한다.
- attackSpeed·power·maxHealth 몰아주기가 다른 선택을 압도하면 승인 없이 공식을 재변경하지 않고 배치 결과를 기록해 후속 밸런스 결정으로 넘긴다.
- UI 전투력은 설명 지표일 뿐 승률 예측치가 아님을 표시해 숫자를 절대 성능 보장으로 오해하지 않게 한다.

## 5. 검토 필요 항목 평가 — 구현 제외

- **2배속:** 반복 관전 시간을 줄이는 장점이 있고 코어 변경 없이 한 렌더 프레임의 fixed step 소비량만 조절할 수 있다. 사운드 중첩과 화면 효과 수명이 빨라지는 문제가 있어, 추후 `playbackRate`만 표현 계층에 추가하는 안을 권장한다.
- **3판 2선승:** 대진의 우연성을 줄이지만 라운드별 체력·분노·쿨다운 초기화, seed 파생, 결과 스키마와 배치 비용을 결정해야 한다. 단일 경기 스탯 밸런스를 먼저 검증한 뒤 별도 설계가 필요하다.
- **최대체력 기반 크기:** 성장 체감은 크지만 렌더 크기만 바꾸면 hurtbox와 어긋나고 물리 크기까지 바꾸면 사거리·겹침·로프 경계가 달라진다. 구현한다면 우선 렌더 전용의 작은 상한 배율을 검토하되 이번 계획에는 반영하지 않는다.

## 6. 완료 기준

- 설정 화면에서 활성 스탯에 총 10점까지 배분·회수·초기화할 수 있고 기준값 아래로 내려가지 않는다.
- 전투 미리보기, 전투력, 관전, headless와 JSON 결과가 동일한 스탯 규칙 snapshot을 사용한다.
- moveSpeed를 포함한 7개 활성 스탯은 명시된 공식대로 전투에 반영되고 luck는 표시·보존되지만 규칙과 RNG에 영향을 주지 않는다.
- 기존 결정성, 60초 종료, 링 경계, 단일 hit, 로프 드롭킥 카운터 면역과 18 tick 지연 카운터 테스트를 모두 유지한다.
- 설정 화면과 새 컨트롤, 스탯 공식 및 결과 데이터 변경을 `README.md`에 기록한다. `docs/todo.md`는 별도 사용자 지시 없이 수정하지 않는다.

## 7. 구현 후 배치 기준선

2026-07-30에 동일한 seed 0~999와 고정 Blue Bull을 사용해 P1 기본값 및 한 스탯 10점 집중 투자를 비교했다.
