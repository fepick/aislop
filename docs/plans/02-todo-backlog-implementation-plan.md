# 02. TODO 백로그 구현 계획

작성일: 2026-07-29  
관련 문서: `docs/todo.md`  
대상: 버그 픽스 2건, 개발 확정 4건  
목표: 현재 결정적 전투 시뮬레이션을 유지하면서 전투 행동 분포, 선수 구분, 타격 피드백, 카운터와 사운드를 단계적으로 추가한다.

## 1. 현재 상태와 공통 원칙

- 일반 공격 AI는 사거리와 쿨다운을 만족하는 `KICK`, `PUSH`, `DROP_KICK`을 균등 선택한다. 이 때문에 일반 드롭킥이 반복되고 밀기가 상대적으로 드물게 보인다.
- P1과 P2는 같은 `red_comet_sheet.png`를 사용한다. P2는 좌우 반전과 파란 HUD/바닥 표식만 적용되어 선수 본체가 구분되지 않는다.
- 코어는 `ACTION_STARTED`, `HIT`, `CRITICAL` 등의 결정적 이벤트를 만들고 렌더러가 이를 소비한다. 화면 흔들림과 사운드는 이 이벤트를 읽기만 하며 전투 상태나 RNG를 변경하지 않는다.
- 변경은 **1단계 버그 픽스 → 2단계 카운터 규칙 → 3단계 화면·사운드 표현** 순으로 구현한다. 각 단계마다 결정성 및 headless/관전 결과 일치 테스트를 통과한 뒤 다음 단계로 진행한다.
- 전투 규칙 또는 RNG 소비 순서가 바뀌는 단계에서는 `rulesVersion`을, AI 선택 정책이 바뀌는 단계에서는 `aiProfileVersion`을 올린다. 결과 필드가 추가되면 `resultSchemaVersion`도 올린다.

## 2. 1단계 — 우선 버그 픽스

### 일반 드롭킥 비활성화와 밀기 유지

**관련 TODO:** 버그 픽스 1

- `DROP_KICK`의 AI 가중치를 `0`, `KICK`과 `PUSH`의 가중치를 양수로 두고, AI가 고정된 후보 순서와 seed RNG로 가중 선택하도록 변경한다. 기본 프로필에서는 일반 드롭킥이 절대 선택되지 않으며 `ROPE_DROP_KICK`의 조건과 `ropeDropkickChance`는 그대로 유지한다.
- 행동 상수와 렌더 프레임은 삭제하지 않는다. 일반 드롭킥을 규칙에서 제거하는 대신 AI 프로필에서만 비활성화하여 향후 다른 프로필이나 직접 입력에서 재사용할 수 있게 한다.
- `PUSH`는 현재처럼 피해와 넉백을 주는 공격으로 유지한다. 밀기 선택률과 명중률을 결과에서 검증할 수 있도록 행동별 시도·명중 카운터를 추가하고 배치 집계에 반영한다.

**위험과 검증**

- 후보 배열에서 단순히 드롭킥을 삭제하면 RNG 호출 수가 달라지므로 기존 seed의 승패는 바뀔 수 있다. 변경 후 새 골든 결과를 고정하고 동일 버전 안에서만 재현성을 보장한다.
- 1,000개 고정 seed에서 일반 드롭킥 시도 수가 0이고, 밀기 시도 수가 0보다 크며, 로프 드롭킥 시도 수가 0보다 큰지 확인한다.
- 사거리 밖에서는 접근하고, 모든 유효 공격의 쿨다운 중에는 안전하게 대기하는 기존 fallback을 회귀 테스트한다.

### P2 전용 파란색 선수 에셋

**관련 TODO:** 버그 픽스 2

- `red_comet_sheet.png`와 동일한 2172×724 RGBA, 가로 4프레임, 동일 피벗·바닥선을 가진 `blue_bull_sheet.png`를 `asset/player_sprite/`에 추가한다.
- P2 에셋은 마스크·상의·하의·부츠의 붉은 부분을 파란 계열로 교체하되 피부, 흰색 장식, 투명 배경은 유지한다. 런타임 tint가 아니라 별도 정적 에셋을 사용해 브라우저별 합성 차이와 매 프레임 처리 비용을 피한다.
- asset manifest와 loader가 선수별 시트를 제공하도록 바꾸고, 경기장 선수와 HUD 초상화 모두 `player.id`에 맞는 시트를 사용한다. P2의 기존 좌우 반전, 이름, 파란 HUD 색상은 유지한다.

**위험과 검증**

- 두 시트의 프레임 크기나 피벗이 다르면 포즈 전환 시 위치가 튄다. 파일 크기, 알파 채널, 프레임 수를 자동 검사하고 네 포즈를 나란히 캡처해 바닥선과 방향을 육안 비교한다.
- P1은 빨간 의상, P2는 파란 의상으로 본체와 초상화에서 즉시 구분되는지 데스크톱 및 가로 모바일 크기에서 확인한다.
- 에셋 변경은 시뮬레이션 JSON, RNG, 승패에 영향을 주지 않는지 같은 seed로 전후 결과를 비교한다.

## 3. 2단계 — 카운터 규칙

**관련 TODO:** 개발 확정 2

### 규칙과 데이터 흐름

- 카운터 확률은 `clamp(0.05 + insight × 0.01, 0.05, 0.45)`로 정의한다. 기본 간파 10의 확률은 15%다.
- 각 유효 피격 후보에 대해 피해 적용 직전에 방어자의 전용 counter RNG 스트림으로 한 번 판정한다. 성공하면 원래 공격의 피해·경직·넉백·분노 증가를 모두 무시하고, 방어자가 공격자에게 즉시 반격한다.
- 반격은 `PUSH`의 기본 피해·넉백·경직을 사용하고 치명타가 발생하지 않는다. 애니메이션은 방어자의 밀기 프레임을 짧게 표시하되, 이미 확정된 다른 동시 공격 판정은 취소하지 않는다.
- 카운터로 발생한 반격은 다시 카운터 판정의 대상이 되지 않는다. KO와 동시 공격은 기존의 동시 적용 원칙을 유지한다.
- 카운터 전용 RNG를 `mixSeed`의 신규 고정 태그로 파생해 기존 AI 선택 및 치명타 RNG와 분리한다. headless와 관전 모드 모두 같은 코어 판정과 RNG를 사용한다.

### 이벤트와 결과

- 코어 이벤트에 `COUNTER`를 추가한다. `actorId`는 카운터 성공자, `targetId`는 원래 공격자, `actionType`은 `PUSH`, `value`는 반격 피해다.
- 렌더러는 `COUNTER`를 파란색 피해 숫자와 `COUNTER` 라벨로 표시하고 성공자를 밀기 포즈로 그린다.
- 선수 결과에 `countersAttempted`, `countersSucceeded`, `counterDamageDealt`를 추가하고 배치 결과에 평균 성공 횟수와 성공률을 추가한다.

### 위험과 검증

- 카운터 성공 시 원래 공격자의 `attacksHit`와 피해량은 증가하지 않으며, 카운터 성공자의 카운터 지표만 정확히 한 번 증가하는지 단위 테스트한다.
- 간파 최소·기본·상한 값의 확률, 고정 RNG에서 성공/실패, 카운터 재귀 방지, 동시 공격 중 한쪽/양쪽 카운터, 카운터 KO를 테스트한다.
- 동일 seed 재현성, 관전/headless 일치, 1,000경기 확률 분포를 확인한다. 밸런스 검증에서는 간파 0/10/40의 성공률과 승률을 같은 seed 세트로 비교한다.

## 4. 3단계 — 화면 흔들림과 사운드

### 데미지 기반 화면 흔들림

**관련 TODO:** 개발 확정 1

- 렌더러가 `HIT`, `CRITICAL`, `COUNTER` 이벤트의 실제 피해를 받아 흔들림을 누적한다. 피해 10 미만은 흔들지 않고, 10~19는 6px·6프레임, 20~29는 12px·9프레임, 30 이상은 20px·12프레임으로 적용한다.
- 흔들림은 경기장과 선수에만 적용하고 HUD와 종료 오버레이는 고정한다. 렌더 전용 수학 함수로 tick/남은 프레임에서 오프셋을 계산하며 `Math.random()`과 시뮬레이션 RNG를 사용하지 않는다.
- 같은 렌더 프레임에 여러 강타가 들어오면 가장 강한 세기와 가장 긴 남은 시간을 사용하고 최대 20px로 제한한다.

**위험과 검증**

- 캔버스 가장자리 노출을 줄이도록 월드 레이어를 흔들림 최대치만큼 확대 또는 클립한다.
- 임계값 경계(9/10/19/20/29/30), 동시 강타, 일시정지, 경기 종료 시 흔들림 종료를 렌더 단위 테스트와 육안 점검으로 확인한다.
- 화면 흔들림 활성화 전후의 시뮬레이션 결과 JSON이 동일해야 한다.

### 공격·피격 사운드

**관련 TODO:** 개발 확정 3, 4

- `asset/sound/attack-shout.wav`에 짧은 “우!!” 음성, `asset/sound/hit-impact.wav`에 짧은 “뻑” 타격음을 추가하고 asset manifest에서 상대 경로로 관리한다. 파일은 재생 지연을 줄이기 위해 시작 시 decode한다.
- 사용자 클릭으로 관전이 시작된 뒤 `AudioContext`를 생성·재개한다. `ACTION_STARTED` 공격 이벤트에는 공격 음성을, `HIT`·`CRITICAL`·`COUNTER`에는 피격음을 재생한다. headless 배치 모드에서는 오디오를 생성하거나 재생하지 않는다.
- 공격 음량은 고정 gain 0.55로 둔다. 피격 음량은 `clamp(0.25 + damage / 50, 0.25, 1.0)`으로 계산한다. 짧은 시간에 겹치는 소리는 최대 4보이스로 제한하고 오래된 보이스부터 중단한다.
- 오디오 로드나 autoplay 해제가 실패해도 경기는 계속 진행하고 UI 상태 문구에만 비차단 경고를 표시한다.

**위험과 검증**

- 음원 라이선스와 상업적 사용 가능 여부를 기록하고, 과도한 피크가 없도록 정규화한다.
- 공격 시작당 음성 1회, 실제 명중당 피격음 1회, 빗나감에는 피격음 0회인지 mock audio 테스트로 확인한다.
- 약한 피해보다 강한 피해의 gain이 크고 1.0을 넘지 않는지, 일시정지 중 새 소리가 발생하지 않는지, 재시작 후 중복 listener가 생기지 않는지 확인한다.

## 5. 완료 기준과 회귀 검증

- 자동 테스트는 RNG 골든 시퀀스, 일반 드롭킥 0회, 밀기 및 로프 드롭킥 유지, P2 에셋 매핑, 카운터 공식·효과·지표, 흔들림 등급, 오디오 이벤트 매핑을 포함한다.
- 기존 9개 테스트를 모두 유지하고, 관전/headless의 `mode` 제외 결과 일치와 같은 seed 재현성을 새 버전 기준으로 다시 고정한다.
- 1,000경기 고정 seed 배치를 실행해 종료 보장, 링 경계, 유한 수치, 승률·KO율·평균 경기 시간, 행동별 시도/명중, 카운터 성공률을 이전 기준과 비교한다.
- 수동 검증은 P1/P2 외형 구분, 밀기 모션, 로프 드롭킥 유지, 카운터의 밀기 포즈와 파란 피해 숫자, 피해별 흔들림 차이, 사용자 클릭 후 공격·피격 사운드를 확인한다.
- 실행 방법이나 에셋 구조가 바뀌면 `README.md`를 갱신한다. 구현 완료 후에도 `docs/todo.md`의 이동·삭제·완료 표시는 별도의 사용자 지시가 있을 때만 수행한다.
